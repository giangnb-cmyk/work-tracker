Hướng dẫn setup Work Tracker

Runbook dựng hệ thống trên máy mới, làm theo thứ tự từ trên xuống. Hệ thống có 3 phần: Supabase (data + auth, cloud, dùng chung), Web (Vercel), Bot Discord (self-host trên MỘT máy).

Các key nối 3 phần với nhau — bảng chi tiết từng biến ở mục 2, 3, 4.

1Supabase — nền của cả web lẫn bot

Project đang chạy: ref vlsskdwcfcmyubyrtwhn → URL https://vlsskdwcfcmyubyrtwhn.supabase.co.

Máy mới nối vào project có sẵn thì chỉ cần làm bước 1.5 (lấy key). Các bước 1.1–1.4 chỉ dành cho lúc dựng project Supabase MỚI từ đầu.

1.1. Tạo project + bật đăng nhập Google

  1. supabase.com/dashboard → New project (chọn region gần VN).
  2. Tạo OAuth client: Google Cloud Console → APIs & Credentials → Create Credentials → OAuth client ID → type Web application:
    • Authorized JavaScript origins: https://m-plan.easygoing.vn, http://localhost:5173, domain vercel.
    • Authorized redirect URIs: https://<ref>.supabase.co/auth/v1/callback
    Copy Client ID + Client Secret.
  3. Supabase → Authentication → Providers → Google: bật, dán Client ID + Secret.

1.2. Áp schema (migrations)

Nguồn sự thật schema + RLS là supabase/migrations/ (đánh số tăng dần). Chọn 1 cách:

# Cách 1 — Supabase CLI (khuyên dùng)
supabase link --project-ref <ref>
supabase db push

# Cách 2 — dán từng file vào Dashboard → SQL Editor, theo thứ tự 0001, 0002…

Migrations tạo đủ bảng + RLS + realtime + bucket Storage attachments.

1.3. Redirect URLs

Authentication → URL Configuration:

  • Site URL = domain production, vd https://m-plan.easygoing.vn
  • Redirect URLs: thêm https://<domain>/** và http://localhost:5173/** (khi dev)
Thiếu bước này = đăng nhập xong bị đá về trang trắng.

1.4. Admin đầu tiên + allowlist

  1. Mở web, đăng nhập Google 1 lần (tự tạo row trong profiles).
  2. Dashboard → Table Editor → profiles → sửa role = 'admin' (hoặc 'owner').
  3. Web → tab Cấu hình → thêm email/domain được phép đăng nhập. Danh sách trống = ai cũng vào được (chỉ để trống lúc khởi tạo).

1.5. Lấy 2 key (Dashboard → Project Settings → API)

KeyDùng ởTính chất
anon keyweb/.env.local, Vercel env Công khai theo thiết kế — bảo vệ bằng RLS + Auth, không phải bằng giấu key
service_role keyCHỈ bot/.env BYPASS toàn bộ RLS. Không bao giờ đưa vào web/, Vercel, hay commit

3Vercel — deploy web + cổng API

3.1. Nối repo

  1. vercel.com → Add New → Project → import repo GitHub janreng/work-tracker.
  2. Root Directory = web ← quan trọng nhất, sai là build fail.
  3. Framework preset: Vite (tự nhận), output dist — đã có web/vercel.json.
  4. Domain: gắn m-plan.easygoing.vn (Project Settings → Domains). Domain này phải nằm trong Redirect URLs của Supabase (mục 1.3).

3.2. Environment Variables

Nhóm client (VITE_ — vào bundle browser): đặt giống hệt mục 2 — VITE_SUPABASE_URL, VITE_SUPABASE_ANON_KEY (+ tuỳ chọn VITE_ALLOWED_EMAIL_DOMAIN, VITE_APP_URL, VITE_GOOGLE_CLIENT_ID, VITE_GOOGLE_WEB_CLIENT_ID).

Nhóm server (cho serverless web/api/* — không lộ ra browser):

BiếnÝ nghĩa / lấy ở đâu
SUPABASE_URLCẦN CHO /api Giống VITE_SUPABASE_URL — để /api verify JWT của user gửi lên
SUPABASE_ANON_KEYCẦN CHO /api Anon key — KHÔNG phải service_role (service_role cấm lên Vercel)
NOTION_SYNC_SECRETTUỲ CHỌN Chuỗi bí mật tự đặt — bot dùng để gọi cổng Notion. Phải trùng biến cùng tên trong bot/.env
DISCORD_WEBHOOK_URLTUỲ CHỌN Webhook kênh Discord nhận thông báo "task hoàn thành" từ web. Discord → Channel Settings → Integrations → Webhooks

4Bot Discord — chỉ trên MỘT máy

4.1. Tạo Discord app

  1. discord.com/developers/applications → New Application → tab Bot.
  2. Reset Token → copy (dán vào .env bước 4.2).
  3. Bật MESSAGE CONTENT INTENT — bắt buộc, bot đọc nội dung khi được tag.
  4. Tab OAuth2 → URL Generator: scope bot, quyền Send Messages, Read Message History, Manage Threads, Manage Channels, Create Posts (3 quyền sau cho sync bug forum) → mở URL, mời bot vào server.

4.3. settings.json — nút cấu hình chính

File tự giải thích bằng các khoá _note_* ngay cạnh từng mục. Các mục phải đụng khi setup:

MụcÝ nghĩa

reminder_channel_id, standup_channel_id, task_done_channel_id ID kênh Discord cho nhắc hạn / standup / báo task xong (bật Developer Mode → chuột phải kênh → Copy ID). 0 = tắt
bug_forums[]Sync forum bug hai chiều: project_id (uuid từ web) + forum_channel_id + notify_role
bypass_permissionsĐể false (run-bot-safe.bat ép false). Bật = Claude chạy lệnh không hỏi — nguy hiểm

rag_sync_enabled, rag_drive_skip, rag_member_*Kho RAG tài liệu + giới hạn phạm vi member
weekly_report_enabled, weekly_mail, member_dm, member_review Báo cáo tuần vào Sheet · mail draft Gmail · DM điểm tuần · đánh giá AI

4.4. Chạy

Windows:

run-bot-safe.bat     # chạy + tự restart khi crash. GIỮ CỬA SỔ MỞ.
  • Bật cùng Windows: Win+R → shell:startup → shortcut tới run-bot-safe.bat.
  • Lịch tự động (Windows Task Scheduler → Start a program): run-reminder.bat (nhắc hạn ~9h), run-standup.bat (standup T2–T6 ~9h30).

macOS / Linux:

chmod +x *.sh        # một lần sau khi clone (nếu mất quyền thực thi)
./run-bot-safe.sh    # chạy + tự restart khi crash. GIỮ CỬA SỔ TERMINAL MỞ.
  • Lịch tự động bằng cron — crontab -e rồi thêm (sửa path cho đúng máy): 
    0  9 * * *   /path/to/work-tracker/bot/run-reminder.sh
30 9 * * 1-5 /path/to/work-tracker/bot/run-standup.sh
  • Bật cùng máy: System Settings → General → Login Items → thêm Terminal chạy run-bot-safe.sh (hoặc dựng LaunchAgent nếu cần chạy ẩn).
  • Script sync RAG cũng có bản .sh: ./sync-rag.sh, ./sync-drive.sh, ./sync-drive-content.sh.
Chỉ chạy bot ở một máy — 2 bot cùng token = xử lý trùng lệnh.
✅ Test: gõ @bot báo cáo sprint trong kênh cho phép → bot trả lời là xong.

6Đồng bộ Notion TUỲ CHỌN

  1. notion.so/my-integrations → New integration → copy secret = NOTION_TOKEN.
  2. Mở database Tasks trên Notion → ⋯ → Connections → add integration vừa tạo. Làm tương tự với database Projects nếu dùng NOTION_PROJECTS_DB_ID.
  3. Lấy Database ID: URL dạng notion.so/<ws>/<DB_ID>?v=… — chuỗi 32 ký tự.
  4. Điền nhóm env Notion trên Vercel (bảng mục 3.2) → Redeploy.
  5. Bot muốn sync: điền NOTION_GATEWAY_URL + NOTION_SYNC_SECRET trong bot/.env.
  6. Trên web: Cấu hình project → "Liên kết Notion project" chọn project Notion tương ứng.
Bỏ liên kết Notion ở Cấu hình project = task của project đó ẩn toàn bộ icon/nút Notion (task list + task detail) và không tự tạo page Notion nữa. Không cấu hình gì = app vẫn chạy bình thường, chỉ không sync.

7App mobile TUỲ CHỌN

cd web && npm run build && npx cap sync
cd android && ./gradlew assembleDebug     # APK: app/build/outputs/apk/debug/
  • JDK 21 — trỏ qua ~/.gradle/gradle.properties: org.gradle.java.home=<path> (JDK 17 lỗi invalid source release: 21).
  • Android SDK 36 — web/android/local.properties: sdk.dir=<path> (gitignore, mỗi máy tự tạo).
  • Đăng nhập Google native: OAuth client type Android (package com.mio.app.manager + SHA-1 từ ./gradlew signingReport) + đặt VITE_GOOGLE_WEB_CLIENT_ID.
  • iOS: cần macOS + Xcode. Chi tiết đầy đủ: README §4.

8Checklist "app chạy được"

  • Web local npm run dev → đăng nhập Google được, thấy danh sách project
  • Vercel deploy xong → domain production đăng nhập được
  • @bot báo cáo sprint → bot trả lời
  • Tạo task trên web → kênh Discord nhận thông báo (nếu đặt webhook)
  • Tạo task ở project có liên kết Notion → page Notion xuất hiện (nếu bật Notion)
  • Task Scheduler chạy thử run-reminder.bat → tin nhắc đúng kênh
